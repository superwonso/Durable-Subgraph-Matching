# Parallel-structure workloads

`reuse_star_scaling.txt` is the balanced control used by the original CPU
scaling experiment. Its 5,000 root candidates have the same four
eight-neighbor relations. Some third/fourth-label edges use the shifted
`[40,50]` interval, so its independently verified count is 16,959,872 rather
than the naive `5,000 * 8^4`.

`reuse_star_skewed.txt` and `reuse_star_skewed_heavy.txt` are generated by
`benchmark/skewed_reuse_generator.cpp`. They isolate scheduler imbalance:
one root has a wide subtree while the other 4,999 roots are deliberately
small. All query edges share snapshots 1--3, so the expected count is known
without relying on an implementation.

| workload | cold neighbors per label | hot neighbors per label | expected matches |
| --- | ---: | ---: | ---: |
| `reuse_star_skewed.txt` | 2 | 64 | 16,857,200 |
| `reuse_star_skewed_heavy.txt` | 1 | 96 | 84,939,655 |

The formula is

```text
hot_neighbors^4 + 4,999 * cold_neighbors^4
```

Generation commands:

```bash
g++ -O3 -std=c++17 \
  benchmark/skewed_reuse_generator.cpp ours/Utils.cpp \
  -o benchmark/skewed_reuse_generator

benchmark/skewed_reuse_generator \
  benchmark/data/reuse_star_skewed.txt \
  benchmark/data/reuse_star_skewed.qry 5000 2 64 3 42

benchmark/skewed_reuse_generator \
  benchmark/data/reuse_star_skewed_heavy.txt \
  benchmark/data/reuse_star_skewed_heavy.qry 5000 1 96 3 42
```

The balanced and skewed inputs must be reported together. The skewed input
demonstrates load-balance behavior; it must not replace real-data or balanced
throughput measurements. Their row counts differ substantially, so runtimes
are compared old-versus-new within each workload; balanced-versus-skewed
comparisons are limited to scaling, utilization, and imbalance patterns.
